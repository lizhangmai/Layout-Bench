# IHP AnalogAcademy case screening

本文针对 [catalog](../tasks/IHP-AnalogAcademy/catalog.toml) 中 pinned upstream commit
`133ecf657572e021b5921b5a1b7693abfb209623`
逐一审阅 30 个 case，判断它们能否成为公开的 SG13G2
`netlist_to_gds` Layout-Bench 任务。证据只采用仓库内的 case TOML、上游
IHP-AnalogAcademy 源文件、上游教程以及 Layout-Bench 的任务协议。

## 结论先行

当前 catalog 的 30 个 case 中，只有
[T_gate](../tasks/IHP-AnalogAcademy/cases/module_3_8_bit_SAR_ADC.part_2_digital_comps.T_gate.toml)
已经包含可执行 `[task]`、冻结输入、参考 GDS 和 qualification 资产。其余
case 的统一 TOML 目前只是来源记录；`candidate` 不等于可运行任务。
Layout-Bench 明确要求 candidate 在发布前冻结权威 netlist、物理约束、评估
计划和独立 qualification 证据；Qucs/RF 与 testbench 也不能自动变成
`netlist_to_gds` 任务（见 [任务协议](tasks.md#task-design)）。

本次筛选的决策含义是：

- **include**：电路本身适合 Layout-Bench，应进入公开任务准备队列；这不表示
  当前已经可运行，表中的缺口必须完成后才能发布。
- **defer**：原则上有 Layout 价值，但当前存在电路身份、层次依赖、版图对应
  关系或可测性问题；在缺口解决前不应进入公开 Bench。
- **exclude**：当前不是 transistor/netlist-to-GDS 任务；保留为上游来源、
  后端 fixture、EM/RF 研究材料或 supporting source，但不应伪装成公开 Layout
  case。

建议结果统计：**include 11，defer 6，exclude 13**。其中 include 仍需按
下表补齐资产；它们不是现阶段可以直接给用户运行的 11 个任务。

## 公开任务的最低证据

每个 include case 最终都必须拥有一个统一 TOML，并至少冻结：

1. PDK-native authoritative netlist、top subcircuit 和端口顺序；
2. 可执行约束：对象选择、单位、容差、hard/soft、面积与允许的器件/指法
   等价变换；
3. evaluation plan：直接检查候选 GDS 的 artifact/DRC/LVS，并让 post-layout
   仿真真正消费候选 GDS 的抽取结果；
4. 独立生成的 reference GDS/generator、输入快照、license/provenance；
5. positive witness、等价变换、空 top cell、错误器件、short/open、DRC、
   约束和性能 counterexamples，以及重复评估证据。

这些要求来自 [任务配置和输入冻结](tasks.md#task-configuration)、[约束和
评估计划](tasks.md#evaluation-plan) 以及 [qualification 清单](tasks.md#qualification)。
上游已有 GDS 或 extracted netlist 只能作为待审查的 reference/evidence；不能
替代权威 schematic netlist，也不能替代 independent qualification。

## 类型差异

| 类型 | 当前含义 | 对公开 Layout-Bench 的处理 |
|---|---|---|
| 候选 Xschem | 使用 `sg13g2_pr` PDK primitive，通常有 schematic、symbol、testbench 和尺寸说明；但 catalog 只记录 source，尚无 `[task]`。 | 适合作为 include/defer 候选；先用 Xschem-LVS/固定 PDK reader 生成并复核 netlist，再做任务资产。 |
| 已有版图组 | 上游已经有 GDS、LVS/PEX netlist 或 DRC report，例如 OTA 子块、BGR 和 comparator。 | 可显著缩短 reference/qualification 准备，但 GDS 只放 `reference/`，不能直接作为 Agent 输入；必须确认 schematic↔layout 对应关系并独立重跑关键证据。 |
| Qucs/RF source-only | Module 2 的 `.sch` 是 `<Qucs Schematic ...>`，包含外部 Qucs library、50 GHz S-parameter/HB/load-pull 或结果图。 | 不属于当前 transistor netlist-to-GDS；若保留，应另建 RF/EM benchmark 协议。 |
| EM source-only | BJT core/T connection 使用 OpenEMS 生成的 S-parameter 子电路和 custom port geometry，关注电磁场/互连而非 PDK transistor placement。 | exclude 当前 Layout Bench；未来可作为独立 GDS-to-EM 或 layout-to-S-parameter 任务。 |
| Verilog/supporting source | SAR logic 是行为级 Verilog，另有 ADC/DAC bridge、纯 testbench 或 gm/Id demonstration。 | 没有可供 transistor layout 的 PDK netlist；只能作为系统仿真支持材料或 supporting source。 |

## 推荐的落地顺序

1. **保留并维护 T_gate**：它是现有公开可运行基线。
2. **先做小而闭合的 include**：inverter、NAND、C-DAC、bootstrap switch；它们
   的 primitive/端口和教程行为最容易冻结，也能覆盖 digital、passive array 和
   charge-pump 三类布局能力。
3. **再做 reference-rich analog**：canonical OTA（把 full-OTA 版图作为
   reference/qualification 来源）、input pair、output stage、canonical
   comparator（优先使用 part-5 版图和 PEX 资产）。
4. **最后处理高风险模拟层次**：full BGR、startup、switch array；先解决
   source variant、层次依赖、温度/mismatch/array 约束，再进入公开任务。
5. **不把 Module 2 和行为级 SAR 系统塞进当前 Bench**：Qucs/EM 资料另行设计
   RF/EM 任务协议；SAR logic、gmid、测试夹具继续作为 supporting/fixture。

这个顺序仍然需要每个 include case 完成完整 qualification 后才能公开；
“有上游 GDS”只降低 reference 准备成本，不改变任务输入隔离和独立 judge
验证要求。
